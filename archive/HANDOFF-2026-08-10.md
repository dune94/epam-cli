## 3. Cost investigation — conclusion

Three runs measured: **7.50M → 7.08M → 11.72M** input tokens per attempt.

- Duplicate `read_file` was 65% but is **not** the driver — all tool output for an entire attempt
  is ~53k tokens (0.75% of the attempt).
- The driver is the **re-send multiplier**: history is re-sent on every one of ~120 turns.
  Roughly: static prompt ~2.0M (29%), tool results ~3.2M (45%), assistant text ~1.9M (26%).
- `compactions = 0` across 1,154 turns — compaction was disabled as a side effect of the
  caching fix, so nothing bounds history.
- **Cost figures are inflated.** `pricing.ts` charges every input token at full rate; there is no
  cached-token term and no cache rate for any model. MiniMax's real cache discount is unverified.

**Nothing shipped this session reduces cost.** Do not claim otherwise without measuring.

## 6. Gotchas that cost time — do not repeat

- **Never inline `node -e '…'` in `claude.sh`.** Broke the file 3×. The pattern that works is a
  separate `.js` file invoked as `node script.js args` — see `lib/lint-staged-scope.js`.
- **Never use `git stash` for baseline comparison.** It failed to pop and reverted source files;
  recovered from the stash entry. Use a throwaway worktree.
- **`git checkout -- <file>` reverts to HEAD, not to your working state.** Cost a day's edits
  once. For mutation testing, back up the file and `cp` it back.
- **`_scope_lock` in `claude.sh` is dead code** — defined, never called. Three test files exercise
  it. Its *generic* half (lock files owned by other stories) is real protection that does not run.
- **`openrouter.sh` is a 10-line shim that `exec`s `claude.sh`** — the metrolinx runs use it, so
  `claude.sh` edits do apply.
- The engine's `perimeter_apply` (`lib/codeline-write-perimeter.sh`) **is** stack-agnostic and
  correct; it locks by branch state.

`useContent.ts` carries `fixVerified: true` with a prescription reading "No code change

obtain one field. Three options:

IS exported but only returns prompt TEXT. The actual runner is `runCodeGraphDetective(story,
logDir, opts)` at spec-mode-runner.js:5181 and is NOT exported. So this means exporting it plus
writing a driver that supplies story/logDir/agent-invocation env and merges the result back into
`fixSiteAnalysis`. A build, not a call. Do it fresh, test the driver before spending an agent call.

**B — Add an operator switch** `SKIP_STORY_VERIFIED_SITE_DEMAND=1`, in the same family as the
existing `SKIP_STORY_LINT_GATE` / `SKIP_STORY_TSC_GATE`. Off by default. Not hardcoding — an
operator decision for one run. Gets a writer run immediately with that one check off.

**C — Flip the gate default** so absent means NOT required. Argued against: it silently un-gates
every PRD written before the field existed, which is the failure the gate was added to catch.

Recommendation: **B** for a run tonight, **A** if the data should be right.
