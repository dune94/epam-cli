# POC: AMSD pipeline → Claude workflow + CodeMie web workflow YAML

Status: PLAN APPROVED 2026-10-15 — branch `poc/workflow-port`. Tracked plan of record for the POC; results are appended under *Results* as each step completes.


## Context
The operator wants a proof of concept: the AMSD pipeline expressed as a **Claude workflow** and, once that works, as a **CodeMie web workflow YAML**.

- The current bash/js/py pipeline stays the source of truth and **must not be touched**. Later changes are carried into both forms by regeneration.
- The plan must state which pipeline features each form carries, carries differently, or cannot carry.
- It must also be a tracked document in the repo.

**Scale** (from the explorations):
- `orchestrations/scripts`: 196 sh (about 62k lines), 152 js (about 42k), 116 py (about 14k).
- 141 templates, 42 seam profiles, 47 canonical agents.
- 36 ordered steps in one phase run (`run-agent-orchestration.sh`, "RAO" below).
- 3 checkpoint stages, 2 of them pauses.

## Design decisions (operator, 2026-10-15)
1. **Two pipelines, in both forms.** Pause 1 (post-roster) is the boundary, as in the bash pipeline.
   - **Pipeline 1 is static: Codeline, Agents, then pause 1.** App-level agents read Jira, find the codelines, mint and review the roster, assign roles, and build and review the project prompts. Its shape is fixed per pipeline version, not per project.
   - **Pipeline 2 is dynamic: Spec, pause 2, Writer.** It is generated from pipeline 1's results, and it keeps the bash pipeline's seam design:
     - each minted role binds to the seam it inherits from its ancestor (`invocation-profiles.json` `agentSeams` / `seamPatterns`);
     - its ladder position, tool grant and SI derive from that seam's base SI;
     - there are no agent-named personas.
2. **One pipeline 2 per codeline.** Lanes run one after another, and a codeline's release lines are steps inside its pipeline. This matches the CodeMie assistant names "Pipeline {codeline} {agent}".
3. **The cache is per codeline,** both for pipeline 1's outputs and for each generated pipeline 2 (memory `fb_cache_by_codeline_disobeyed`).
4. **Providers in scope: `claude` and `codemie-claude` only.**
   - `claude` is the claude set, on subscription.
   - `codemie-claude` is the codemie set: Claude through the wrapper with CodeMie SSO.
   - Excluded: openrouter/minimax, copilot, openai, cursor, codemie-web's non-Claude models, replay/mockserver.
   - Ladders are read only from `config/llm-defaults.claude.json` and `config/llm-defaults.codemie.json`.
   - CodeMie YAML assistants use CodeMie's Claude models only.
   - **Not verified:** that the Workflow tool is available inside `codemie-claude`. Checked first, at £0.
5. **Pipeline 2 is generated by deterministic code, not an agent.** Pipeline 1's agents already made the judgements; an LLM writing the graph could drift from the seam design.

## Hard constraints
- **No change to any pipeline file.** That covers `orchestrations/**`, `orchestrations-installer/**`, `npm-package/**`, `src/**`, the agents, templates and config, and every generated artefact. New files only:
  - `poc/workflow-port/**`
  - `.claude/workflows/amsd-p1.js`
  - `change-log/POC-CLAUDE-WORKFLOW-AND-CODEMIE-YAML.md`
  - `test/unit/poc/**`
- **Nothing hand-copied.** Prompts are rendered by the pipeline's own `renderEngineTemplate` (`scripts/lib/engine-prompt.js:242`) and `buildPrompt` (`lib/prompt-library.js:267`), which are called, not copied. Seams, ladders and schemas are read from `invocation-profiles.json`, `llm-defaults.<set>.json` and `seam-output-contracts.json`.
- **Waits for a yes:** live tokens; any CodeMie create (the operator names the project, and it stays private); any codeline other than a **copy**. No Metrolinx remote access and no PRs.

## Architecture
```
pipeline data (templates, seams, ladders, contracts)
        │  generate-p1.js (static, per pipeline version)
        ▼
PIPELINE 1  ──agents──►  per-codeline results: prd slice, codeline scope, roster, role
(Claude wf / CodeMie)    assignments, project prompts        → cache/<codeline>/p1/
        │  pause 1 (operator approves results + the generated pipeline 2s)
        │  generate-p2.js (deterministic; seam design)
        ▼
PIPELINE 2 per codeline ──► Spec ─ pause 2 ─ Writer (ladder, self-heal, review, gates)
(Claude wf / CodeMie)        → cache/<codeline>/p2/{ir.json, workflow.js, codemie.yaml, inputs.sha}
```

**Intermediate representation (IR).** Each pipeline is built first as an IR, then emitted by two emitters:
- `emit-claude-workflow.js`
- `emit-codemie-yaml.js` (comes second; it renders the IR proven by the Claude workflow)

The IR holds:
- each step, with its seam, model per ladder rung, tool grant, rendered SI and prompt, and output schema;
- the edges between steps: next, retry/escalate, remediate, pause.

**Per-codeline cache:**
- **Pipeline 2:** a codeline's pipeline 2 is regenerated only when the hash of its inputs changes. The inputs are that codeline's pipeline 1 results, the generator version, and the seam, ladder and contract files.
- **Pipeline 1:** reuse follows the pipeline's own decision (`_run_agent_mint`, `lib/mint-and-spec.sh:158-261`; `.prompt-cache/<codeline>/`, `project-prompt-builder.js:613`). That decision is read and called, never re-implemented. Its results are stored per codeline even where the bash pipeline still keeps minted-agent files per project. Any such difference is logged in the change-log as a finding.

Deterministic steps run inside agents by calling the **pipeline's own scripts** through Bash under `~/.claude/bin/bounded`. These are git and worktrees, test suites, tsc/eslint and the HEAD progress check. Each is either called that way or listed as a gap; none is re-implemented.

## CodeMie YAML: known vs unknown
- **Known:**
  - `assistants` (inline, or `assistant_id: <uuid>` pointing at a stored assistant);
  - `states[].next.state_id`, `resolve_dynamic_values_in_prompt`, `interrupt_before`;
  - execution `resume`/`abort` (SDK);
  - `mode: Sequential|Autonomous`.
- **Unknown:** conditional edges, loops, parallel branches, retries, passing data between states, output schemas. These are confirmed before step 6, from CodeMie docs supplied by the operator or from one private probe workflow after a yes.

**Behavioural difference to state in every report:** the bash pipeline is deterministic outside the model. Both forms move its deterministic steps into agents, which adds cost and nondeterminism.

**Pipeline findings to record (no change in this POC):**
- Exit 2 is overloaded: insufficient context, ESCALATE, "no verdict" and insufficient ACs all exit 2.
- A CPA BLOCK exits 3, the same code as HALT_REVIEW.
- The three launchers retry differently.
- `orchestrate.sh` always passes `--reset`.
- `run_pre_phase_assessment` is defined twice.
- The codemie-web memory names an old path; the code is now in `plugins/providers/codemie-web/`.

## Steps
1. On branch `poc/workflow-port`, write `change-log/POC-CLAUDE-WORKFLOW-AND-CODEMIE-YAML.md` (this plan, the matrix, the findings and a decisions log) and commit it. **No push.**
2. Red test, then `generate-p1.js` + the IR + the Claude emitter, then green.
3. Red test, then `generate-p2.js` (fed with a real pipeline 1 result: run 9's cxshared roster and prompts, **read** from the install, not edited), then the per-codeline cache, then green.
4. **£0 dry run:**
   - check that the Workflow tool exists under `codemie-claude`;
   - then run pipeline 1 to pause 1, generate pipeline 2, and run pipeline 2 with `args.mock=true`. Mock agents answer from the contract and the input they receive.
   - Planted cases: gate fail → remediation → writer; review reject → escalation; both pauses and their resumes; cache hit on an unchanged codeline; cache miss after a planted change.
   - Paths are checked from `journal.jsonl`. An unreached path is UNPROVEN.
5. **The operator's yes → one live slice** (AMSD-2974, a cxshared copy), once under `claude` and once under `codemie-claude`. Compare with run 9: verdicts, files changed, review outcome, tokens.
6. Confirm the CodeMie grammar, then the YAML emitter and its tests. **The operator names the project**, then the stored assistants are created and `codemie sdk workflows create` runs (both private), then a run on the same slice.
7. Write the results into the change-log document: proven, carried differently, gaps, and a recommendation.
