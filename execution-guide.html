amsd-pipeline — Execution Guide

Run a ticket, watch it, pause it, resume it, stop it.

The one command. Everything on this page is optional detail around a single script — orchestrations/scripts/pipeline: 
cd <install>
./orchestrations/scripts/pipeline --jira AMSD-1234
That is a complete run. Add --dry-run to check first without spending, or --list to see what this install can run. The script resolves the project, the stack and the credentials itself, refuses to start with a plain list of anything missing, and then hands off to the tested launcher — it reimplements no pipeline logic.

1. Before you run

Install first — see install-guide.html or INSTALL.md. A run needs three things that the installer does not supply for you:

WhatWhere it lives
Credentials for the stackthe install's .env
Jira credentials<install>/orchestrations/jira/<project>.env — copy it from a previous install; install.sh does not carry it
The codeline rootJIRA_CODELINE_ROOT, the directory holding the repositories the run may modify
Check before spending. --dry-run resolves the ticket, the project and the stack, and reports what is missing, without making a model call.

The pre-launch — what every launch checks first

With the shared components installed (install guide 2d), every launch runs the shared pre-launch before any model call: the bash launchers through require_preflight (after the pipeline's own pre-flight), the Claude workflows from their launch. Any red stops the launch; nothing is spent. The checks:

CheckGreen when
preflightthe pipeline's own pre-flight passes, unchanged (runner, PRD, ladders, dashboards, self-heal routing, project readiness)
langfuseLangfuse answers, and a launch trace is written and read back under the run's session id
seedevery seeded prompt and agent file is byte-identical to a recorded run of the launched ticket, and none names another ticket
cachethe seeded codeline's cache has its prompt set, agent files, completion marker and per-prompt entries; prompts without an entry are named and are at most the launch's --max-rebuild (0 when unstated)
costthe ledger records a priced call, and every model on the active ladders has a price
alonenothing else is working against the install (its own registered services excepted)
memoryavailable memory, less 3 GB kept for the host, covers the run
no-timeoutno time limit above the launch can cut an agent off
checklistthe 12-item run checklist has no red item (items decided later in the run are "not yet")

The report is <run>/prelaunch-leg-1/prelaunch.json. To run it on its own:

npx amsd-pipeline-shared prelaunch --install <install> --project <project> --run-id <id> --out <dir> \
  [--ticket <KEY> --runs <a recorded run's runs dir>] [--codeline <codeline>] [--max-rebuild <n>] [--prd <file>]
Right before launching, look at the machine. The memory check reads one moment. If another memory-heavy job is running or about to start — another pipeline, a flow, a claude -p, a test suite or a build — wait for it to finish.

2. Run a ticket

cd <install>

# what this install can run
./orchestrations/scripts/pipeline --list

# check without spending
./orchestrations/scripts/pipeline --jira AMSD-1234 --dry-run

# run it
./orchestrations/scripts/pipeline --jira AMSD-1234

The ticket prefix chooses the project: each project declares its own JIRA_PROJECT_KEY. The wrapper refuses to start with a plain list of anything missing, then hands off to the tested launcher. It reimplements nothing.

To run on a different stack for one run:

EPAM_PROVIDER_SET=copilot ./orchestrations/scripts/pipeline --jira AMSD-1234

The stacks are the ones orchestrations/config/provider-sets.json declares: claude (default), openrouter, codemie, copilot, codemie-web, mockserver. The wrapper refuses to start when that stack's runner is not on PATH, or when the project has no overlay for it (config.<stack>.env in the project's config folder).

3. Where to watch it — dashboards, Langfuse, Grafana

Defaults below. If another install already holds a port, this install steps every port by +10 and records what it used. Read the real values for an install with:

grep '^OBS_\|^LAUNCH_' <install>/.pipeline-services-state.env
WhatDefault URLShows
Pipeline dashboardshttp://localhost:8092The run — pages below
Langfusehttp://localhost:3100Every model call: prompt, reply, tokens, cost, latency
Grafanahttp://localhost:3001Cost and throughput over time
Launch dashboardhttp://localhost:8099Queue and launch runs from a browser
Dashboard pageUse it for
/monitor.htmlLive progress — keep this open during a run
/agent-activity.htmlWhat each agent did, per story, with its tool calls
/health.htmlSelf-healing events and whether the run is recovering
/scorecard.htmlThe end-of-run result
/quality-dashboard.htmlGate outcomes and coverage
/cpa-details.htmlCost and iteration estimates per story
Before the first run the dashboards serve 404 for /logs/… and /prd.json. That is expected: pre-run-reset.sh mounts them when a run starts.
Langfuse only records when the install was made with --replay on and both LANGFUSE_PUBLIC_KEY and LANGFUSE_SECRET_KEY are set. A run that is not recorded cannot be replayed. Recorded runs are archived to orchestrations/cassettes/<project>-<run-id>/ by the cassette watcher started with the services.

4. Pausing for review

Two checkpoints, each opt-in, so you can approve what the run produced before it spends more:

VariableStopsReview
EPAM_PAUSE_AFTER_AGENT_MINT=1After the roster is minted and assigned, before the spec passThe agents and who owns each story
EPAM_PAUSE_BEFORE_WRITER=1After inputs are ready, before the writer changes codeThe PRD and the story inputs
EPAM_PAUSE_AFTER_AGENT_MINT=1 EPAM_PAUSE_BEFORE_WRITER=1 \
  ./orchestrations/scripts/pipeline --jira AMSD-1234

At each pause the run prints the files to inspect and the exact command to continue.

Informing a brownfield run with an estimation assessment

Set EPAM_ESTIMATION_MANIFEST in the project's config.env to the folder the estimation application wrote its output to. After ingest the run prints [estimation] N ticket(s) assessed; each ticket's record is at orchestrations/logs/estimation/<KEY>.json, and the spec agent, detective, CPA, writer, reproducing-test writer and reviewer receive it. At either pause, that record is the assessment the agents worked from.

5. Resuming a paused or interrupted run

A resume continues the SAME run from its checkpoint. It does not re-mint the roster and does not re-assign over your edits.

EPAM_RESUME_RUN=<run-id> bash orchestrations/scripts/<launcher> --yes

The run id is printed at every pause (for example 20260907T111214Z). To run straight through the remaining stages, set both pause variables to 0 on the resume.

6. Stopping a run, and cleaning up after it

# stop the run
pkill -f tier3-.*-run.sh ; pkill -f run-agent-orchestration.sh

# stop this install's services
bash orchestrations-installer/pipeline-services.sh --stop --dest <install>
Killing the run is not the whole job. The observability and launch stacks keep running — postgres, langfuse, grafana, the dashboards, the launch UI (and, on a 2.0.80 install only, ClickHouse, which is not used — see install guide 2d). They hold memory, and their networks hold subnets that the next install needs. Stop the services as well.

7. What a run cost

Every priced call is appended to the run's ledger:

<install>/orchestrations/logs/phase-cost.jsonl

Each line carries the agent, the resolved model, tokens in and out, and task_cost_usd. Grafana charts the same data over time, and Langfuse shows the individual call.

8. When a run will not start

MessageCause
.env is missingCopy .env.example and fill it in.
JIRA_TOKEN is not setThe project's secrets file is missing — copy orchestrations/jira/<project>.env from a previous install.
no provider configuredNo provider set resolved. Set EPAM_PROVIDER_SET, or run from an install whose project config declares one.
JIRA_CODELINE_ROOT: unbound variableExport it, pointing at the directory holding the codelines.
refusing to launch: the dependency manifest is not validThe project's dependency-check.json failed review. The message names the issue; nothing was reset and nothing installed.
Pre-flight ✗ langfuse: NOT servingThe stack is down or still starting. On a 2.0.80 install (2.0.81 no longer has it) pipeline-services.sh --start also starts ClickHouse, which is not used: start postgres and redis, then the Langfuse server on its own (install guide 2d), and re-check.
Pre-launch ✗ cacheThe seeded codeline's cache lacks per-prompt entries, so those prompts would be rebuilt (paid). Carry the recorded run's entries into the cache; or, to accept a named few, launch with --max-rebuild <n>.
Pre-launch ✗ seedThe seeded prompts or agent files are not the launched ticket's. Seed the codeline again (install guide 2d).
Pre-launch ✗ aloneAnother process is working against the install. Let it finish, or stop it, then re-check.
Pre-launch ✗ costA model on the active ladders has no price in config/model-pricing.json. Add the vendor's price (the file says where it came from).
