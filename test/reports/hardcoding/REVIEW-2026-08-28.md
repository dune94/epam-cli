## Reviewed and deliberately NOT reduced

**5 — numeric thresholds (81).** Five sit inside help/log strings rather than logic. Shaving
them would add scanner complexity for almost nothing, and `"To override:
GATE_ESCALATE_THRESHOLD=200"` is drift-prone documentation that deserves to stay visible.

**8 — domain vocabularies (13).** About six are the engine's OWN enums — roster modes
`['derive','canonical']`, constraint kinds, the codegraph plugin's own command list. Those are
definitional: a new value means new code either way. The other seven are real and worth fixing
in the code rather than in the scanner:
- `brownfield-context.js` `['summary','description','labels']` — a tracker's field names, which
  are per-tenant, the same class as the customfield ids category 7 exists for.
- `verification-plugin.js` `['typecheck','type-check','tsc',...]` and `['test','tests',...]` —
  guessing a client repo's npm script names. Measured live on 2026-08-28: "[tsc-verify]
  MOCK3-1: the project declares no typecheck command — the check could not run".
- FOUR copies of the provider list in `src/` (`provider.ts`, `doctor.ts`, `keys.ts`,
  `UserCommand.ts`) and they have ALREADY DRIFTED — one carries codex/copilot, three do not.
  One list, four homes, no single point of maintenance.

**10 — model-facing prose (11).** All fallback personas embedded in code
(`[ -z "$reviewer_profile" ] && reviewer_profile="You are a change reviewer..."`). These are the
most valuable findings in the audit, not the least: one prompt, one file, no fallbacks.

**3 — the 15 that remain.** All in the CLI product, none in the pipeline: a 10-entry model
catalogue in `src/cli/repl/DataConfig.ts` and two provider `defaultModel` fields. The
orchestration pipeline's model-identifier count is now zero, which is the number that matters
for stack portability.

## A near-miss worth recording

The first narrowing used `printf '%s'`, which drops the trailing newline and with it each
category's LAST finding — every category read one lower, and 409 would have been reported an
hour early on a fake reduction. Now pinned by a test asserting the untouched categories keep
their exact counts.


## Second pass — the blind spot (379 -> 406)

Moving three script-name lists into the ecosystem file that owns them dropped domain
vocabularies 10 -> 8 EVEN THOUGH the new path was in scope: the pattern matched `= [...]` and
not `key: [...]`. A relocation reading as repair, which is how this audit was defeated on
2026-08-23. Caught by checking the new home was still SEEN rather than trusting the total.

Teaching it object properties surfaced 48 findings it had never seen anywhere. 16 were
JSON-schema `required:` lists — field names, not domain values — and are excluded. `enum:` is
kept deliberately: that IS a vocabulary, and constraining a model's output argues for keeping
it visible.

## Category 4 — urls and ports (40): reviewed, nothing to reduce

- **17 vendor URLs, all in `src/` provider adapters.** `AnthropicProvider` naming
  api.anthropic.com is what makes it that provider, and services.json is for the
  orchestration's OWN services, not vendor APIs. Real findings, low value to relocate: they
  would gain indirection and lose locality. Left visible.
- **9 inside operator messages** ("POST http://localhost:${CONTROL_PLANE_PORT}/resume"). The
  port is already a variable; only the loopback host is literal. services.json declares
  dashboard, grafana, langfuse, phaseGraph, remoteSession and storyApi — but NO controlPlane,
  so there is nothing to read from. Adding that entry is a design addition, not a defect fix,
  and the resume path is not somewhere to make a speculative change.
- The remaining few are a mock harness default, the dashboard validator, and the control
  plane's own bind banner (`0.0.0.0:${PORT}` — a server binding, not a client URL).
